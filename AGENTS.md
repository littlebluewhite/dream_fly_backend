# AGENTS.md

## Build & Run

```bash
docker-compose up -d   # PostgreSQL, Redis, Kafka, Kafka-UI
cp .env.example .env
cargo run              # serves 0.0.0.0:3000; applies ./migrations before accepting connections
cargo run --bin seed   # idempotent dev seed
scripts/smoke.sh       # end-to-end API smoke test; needs the server running + seed applied
```

The seed creates admin/member/coach accounts, courses, products, coupons, venues, posts, plus a
12-month deterministic reporting dataset (24 extra members, enrolments, orders, attendance,
venue-rental bookings, contact inquiries).

The dev database (`dream_fly` in docker-compose) holds the user's working data: drop, recreate, or
reset it only after the user names that action in so many words. A numbered menu pick or "ok" is not
that; experiment on a scratch database instead.

**API contract** — before changing any endpoint's path, auth, request, or response shape, read its
section in `docs/api/integration-contract.md` (endpoints, DTO fields, pagination/money/points
conventions). The frontend integrates against it.

## Architecture

Axum REST API. Each domain is a module under `src/modules/{name}/`, all routes merged under
`/api/v1` in `src/startup.rs`.

### Request flow

```
HTTP → CORS → Request ID → Tracing → Security headers → Rate Limit (EphemeralStore)
     → Body Limit (2MB) → Compression
     → Router (/api/v1/*) → AuthUser extractor (JWT + RBAC) → Handler → Service → Repository → DB
     → JSON response
```

### Module layout

- `model.rs` — sqlx `FromRow` structs + enum types (`sqlx::Type`)
- `dto.rs` — Request (Deserialize + Validate) / Response (Serialize) types, `From<Model>` impls
- `repository.rs` — database queries as free functions taking `&PgPool`, `&mut Transaction`, or `impl sqlx::PgExecutor<'_>` (when one query must run on either)
- `service.rs` — business logic bridging handlers ↔ repositories
- `handlers.rs` — Axum handlers extracting `State<AppState>`, `AuthUser`, `ValidatedJson<T>`, etc.
- `routes.rs` — `pub fn router() -> Router<AppState>`

### State and seams

`AppState::new(db, config, Infra, Overrides)` in `src/state/mod.rs` is the only construction point.

- `Infra` — connection-backed seams with no default: `access_cache` (`AccessCache`), `ephemeral`
  (`EphemeralStore`), `health` (`HealthProbe`). Production: `Infra::redis(conn, kafka_connected)`.
- `Overrides` — IO-free seams where `None` means the production adapter: `email`, `clock`,
  `google_identity`.
- `new` owns the shared reqwest client and the single `TaskTracker` (`background_tasks`).
- All short-lived state goes through `EphemeralStore` (`src/utils/ephemeral.rs`); each owner keeps
  its own keys and policy (`auth::rate_limit`, `auth::otp`, `auth::reset_tokens`,
  `middleware::rate_limit`).
- Test doubles for every seam live in `tests/common/mocks.rs`.

### Authentication & authorization

- `AuthUser` (`src/extractors/auth.rs`) validates the Bearer JWT, then loads active status + roles
  via `auth::access::resolve` through `AccessCache` (active 60s TTL, roles 15min TTL, DB fallback).
- Protected handlers take `auth: AuthUser`; public handlers omit it.
- Role checks: `auth.require_role(Role::Admin)?` / `auth.has(Role::Coach)` / `auth.is_admin()`; roles are the closed `permissions::model::Role` (ADR-0014).
- Wire types: `bindings/` is generated by ts-rs from response DTOs (ADR-0016). After changing a DTO run `WIRE_BINDINGS=write cargo test --test wire_types`, then `npm run wire:sync` in the frontend.

### Database patterns

- Queries use the runtime form `sqlx::query_as::<_, Model>("SQL").bind(val).fetch_*(db).await`, and
  `sqlx::query("SQL").bind(val).execute(db).await` for mutations, so builds need no live database.
- Transactions: `let mut tx = db.begin().await?;` → `.execute(&mut *tx)` → `tx.commit().await?;`
- PostgreSQL enums: `#[derive(sqlx::Type)] #[sqlx(type_name = "enum_name", rename_all = "snake_case")]`,
  bound directly as the Rust enum (`points` still binds with a `$N::point_reason` cast). Value sets
  are owned by each enum's `ALL` + `as_str`.

### Conventions

- Validation: `ValidatedJson<T>` (`src/utils/validation.rs`) deserializes + runs `validator` checks
  → `AppError::Validation`.
- Errors: `AppError` (`src/error/mod.rs`) maps to HTTP status; body is `{"error": "message"}`.
- Pagination: `PaginationParams` (`src/extractors/pagination.rs`) — page=1, per_page=20, max 100.
- Studio time: dates and times are studio-timezone wall-clock; convert with
  `src/utils/studio_clock.rs` (`today()`, `to_utc()` returns `None` on DST ambiguity,
  `has_started()`, `has_ended()`). Contract §3.18 裁決 2.
- Rate limit (`src/middleware/rate_limit.rs`): global per-IP 300/min + auth bucket 10/min, both
  fail-closed (500 when the store is down).
- Config: `config/default.toml` → `config/{APP_ENV}.toml` → env vars `APP__SECTION__KEY`.

### Kafka (optional, `APP__KAFKA__ENABLED=false` by default)

- Services publish domain events with `kafka::outbox::insert_domain_event_tx` inside their business
  transaction; the dispatcher started in `main.rs` drains `events_outbox` to Kafka.
- The consumer (`src/kafka/consumer.rs`) is audit-only: every event lands in `audit_log`, keyed by
  envelope `event_id` (`ON CONFLICT DO NOTHING`). Retry policy: ADR-0013.
- Notifications are written synchronously through `notifications::service`, not via Kafka (ADR-0009).
